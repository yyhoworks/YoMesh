# YoMesh 项目结构

## 当前流程（0.13.0）

配置空间保存设备方案；节点组整理线路与共用出口，规则页同时编辑匹配、出口、启停、顺序和兜底。基础配置、入站为设备预设，DNS 独立设置和导出。普通空间组合共享资源，原生导入空间完整独立保存。所有预览、组合检查和正式导出共用后端 Profile 路径；组合检查不代替下载前的目标内核校验。下文早期目标和阶段记录仅作历史背景，当前行为以 README.md 与 compatibility.md 为准。

## 目标

围绕五种日常对象构建工作台：订阅来源、节点库、节点组、规则库、分流策略。玻璃视觉参考 LocalDNS，编辑动作参考 MR。默认只管理一个配置空间。

## 配置编译

`Profile` 是前端、导入和所有转换器共享的事实来源。它保存稳定 ID，集中完成节点参数、来源、规则集、目标引用、启用状态、正则及循环检查。两种代理编译器调用同一组成员解析结果。

编译模块返回配置与诊断，不访问网络、不启动内核、不改系统。原生验证模块单独负责版本核对、短生命周期进程、超时和临时文件。导出接口只在全部验证成功后生成包。

`Mihomo` 与 `sing-box` 是同一代理出口接口的两个 adapter；`MosDNS` 编译的是该配置的 DNS 域名部分。遇到不等价的节点组模式直接失败，未来有经过验证的等价实现后才扩大支持。

## 当前状态

已实现统一 profile v1、五基础协议（含 SS2022）、两种代理生成器、DNS 生成器、命令行、原生校验、本地服务与网页导出。0.2 将真实订阅、节点、规则、组与策略接入持久化工作区。

`subscriptions.py` 负责下载、格式适配、稳定去重及入库前过滤；`workspace.py` 负责原子快照、备份、修订冲突与引用保护；`services.py` 负责后台更新、计划调度与真实节点 HTTP 延迟测量。测速使用回环地址临时控制端口和随机密钥，不修改宿主机系统代理或 DNS。

网页升级时只迁移旧演示中用户保存的真实订阅地址，不导入缺少连接参数的演示节点与策略。完整节点由真实上游重新解析；旧浏览器快照不删除。节点组预览与导出共用后端 Profile 成员解析。表单编辑时暂停轮询替换，避免覆盖输入。

## 后续阶段

1. 完整节点可视化表单与规则集编辑/删除（当前节点使用统一 JSON 编辑，规则集可新建和查看）。
2. AGE 加密订阅、每订阅独立 DNS、额外协议与扩展的逐目标适配。
3. 配置导出差异、备份恢复入口与更细的能力提示。
4. 登录认证、内核发布与运行态控制。当前仅可信局域网配置管理，不接管网络。

历史拆分提案 `original-plan.md` 是命名前的参考，不覆盖当前三内核兼容要求。
