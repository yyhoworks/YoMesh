# 0.4 规则与节点组

实现参考只读查看的 MR v0.18.0：规则编辑页、规则源 / 订阅管理、节点组列表和新增表单。保留 LocalDNS 玻璃样式与项目 logo，沿用五个主入口。

## 规则集的使用

1. 进入“规则库”，点“添加规则集”。
2. 选手动粘贴、订阅地址或导入文件；填写名称和内容 / 地址，格式可自动识别。
3. 进入“分流策略”，新建或修改规则。
4. 条件来源选“规则集”或“规则订阅”，再选刚添加的内容。可添加多个引用，也可以混入多行域名 / IP 匹配器。
5. 组内、组间分别选择 AND / OR，右侧摘要由后端返回；选择出口与 DNS 后保存。

规则订阅可按分钟间隔或北京时间每天时刻更新；更新失败保留上一次内容与所有引用。删除时检查全部方案的引用。更新期间修改了同一规则来源时，旧任务不会覆盖新编辑。

支持 Clash payload YAML、域名 / CIDR 列表、Surge 六类基础匹配、Mihomo MRS、sing-box SRS / JSON，以及 AdGuard 域名拦截。取反、完整 AdGuard 扩展、文件内部不可展开的 AND / 未支持字段明确报错，不跳过后伪装成功。需要 AND 时，在分流规则条件组中编排。

## 节点组

三类成员可以混选：订阅、单个节点、子组。支持成员搜索、选择搜索结果、清空本类、正则筛选、手动默认成员和成员上下移动。组列表独立滚动，右侧编辑器保留在可操作位置。

“保存并测速”通过临时 Mihomo 内核实际访问测试 URL，展示各节点 HTTP 延迟与失败状态；这不是下载带宽。测速 URL 同时用于支持自动检查的原生组，手动测速超时仅用于工作台测试。保存默认成员只配置后续导出，不声称已切换其他设备的运行内核。

## 兼容与验证

组合规则由统一表达式生成：Mihomo 原生 AND / OR 与 inline rule-providers；sing-box 原生 logical，入站约束作为独立 AND 子条件；MosDNS 按有序分支执行域名逻辑。DNS 不知道查询后的目标 IP，含纯 IP 的 AND 条件不缩减成域名条件。

运行 Mihomo 时，需等待规则集初始化完成后接入流量；监听端口建立或控制接口已有条数均不代表规则集已经可用。实际连通测试先通过同一规则集访问本机 HTTP 服务确认就绪，再检查 AND / OR 的放行和拦截行为。

Windows 42 项测试通过，含两个代理实际 HTTP 连接验证 AND / OR、MosDNS 实际 DNS 查询验证短路和后续兜底、真实 MRS / SRS 编译解码、HTTP 文件上传与引用保护、订阅失败保留和重启持久化。浏览器隔离测试工作区完成了订阅创建、组合规则保存、两种配置包原生导出以及一个真实节点的组内延迟测试。原群晖工作区不使用这些测试样例。

Mihomo 的 fallback / load-balance 与 sing-box 的差异仍需用户在导出时明确选择；不提供定时生效、规则取反、黑洞或 MR 的设备接管和 GeoIP 管理。
